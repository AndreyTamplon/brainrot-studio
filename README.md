# Brainrot Studio

Учебный проект по курсу «Мультиагентные системы»: локальная студия коротких видео. Пользователь задаёт тему, язык, фон и рассказчиков; система исследует тему, пишет сценарий, подбирает изображения, озвучивает реплики и собирает вертикальный MP4.

## Как устроено

Продюсер на Google ADK управляет четырьмя подагентами: исследователем, сценаристом, визуализатором и монтажёром. Они обмениваются структурированными артефактами. Проверки возвращают замечания продюсеру для адресной доработки. TTS, Whisper и FFmpeg используются как инструменты.

- React / TypeScript / Vite — интерфейс; FastAPI — API и очередь заданий.
- Google ADK + OpenRouter — агенты, поиск и модельные проверки.
- Fish Audio / Gemini TTS — озвучка, faster-whisper — распознавание и тайминги.
- FFmpeg / PyAV / Pillow — монтаж и пословные субтитры.
- SQLite — история, события и учёт расходов.

Подробнее: [архитектура](docs/design.md).

## Возможности

- Русский и английский, 1–3 рассказчика, длительность 15–90 секунд.
- Игровые фоны и загрузка собственных материалов.
- Исследование с источниками и иллюстрациями Wikimedia Commons.
- H.264/AAC, 1080×1920, 30 fps, MP4, SRT и отчёт проверки.
- История версий, отмена, восстановление после сбоев и частичные правки без полной перегенерации.
- Контроль расходов и проверки сценария, изображений, звука и таймингов.

## Локальный запуск

Нужны Python 3.12 или 3.13, [uv](https://docs.astral.sh/uv/), Node.js 22+ и FFmpeg/ffprobe в PATH.

```sh
cp .env.example .env
uv sync --frozen
uv run python scripts/bootstrap_media.py
uv run python -c 'from brainrot.media import recognizer; recognizer()'
./run.sh
```

Откройте http://127.0.0.1:8000. Для другого порта: `PORT=8001 ./run.sh`.

Укажите свой `OPENROUTER_API_KEY` в `.env` или через настройки интерфейса. Интерфейс принимает ключ с суммарным лимитом не выше $10 без периодического сброса. Модели и лимиты задаются в `.env.example`. Генерация использует платные API; стандартный предел — $1.50 на задание и $10 суммарно.

Установка пресетов скачивает и перекодирует медиа, первая загрузка Whisper скачивает модель. Готовые ролики, кэши и база не входят в репозиторий: они создаются в `data/`. Предпросмотры голосов появляются только при наличии локальных образцов.

## Docker

После создания `.env`:

```sh
mkdir -p data
docker compose build
docker compose run --rm studio python scripts/bootstrap_media.py
docker compose up
```

На Linux каталог `data/` должен быть доступен для записи UID 1000. Локальный сервер и контейнер не должны одновременно использовать одну базу. Ключ для контейнера храните в хостовом `.env`: изменение только через UI контейнера не переживёт его пересоздание.

## Проверки

```sh
uv run pytest -q
uv run ruff check brainrot scripts tests
npm --prefix frontend ci
npm --prefix frontend test
npm --prefix frontend run build
```

Эти проверки не вызывают платные модели. `scripts/check_runtime.py` проверяет UI/API и настоящий рендер; ему нужен отдельный пустой `DATA_DIR`. `scripts/audit_backgrounds.py` и `scripts/audit_video.py` проверяют уже существующие материалы.

`scripts/smoke.py` и `scripts/acceptance.py` вызывают **платные API**. Smoke запускается при остановленном сервере; acceptance обращается к работающему серверу. Подробности и результаты: [проверки](docs/validation.md).

## Ограничения и данные

Приложение рассчитано на одного локального пользователя и один worker. Это не публичный многопользовательский сервис. При генерации текст, изображения, голосовые образцы и финальная аудиодорожка для проверки передаются OpenRouter и поставщикам моделей; Whisper работает локально.

Автоматические проверки не гарантируют фактическую точность, качество юмора или точное сходство голоса. Перед использованием результата нужен просмотр человеком. Неопределённые расходы после сетевых ошибок остаются зарезервированными до сверки с провайдером.

Медиа не включены в исходники. Персонажи, голоса и игровые записи имеют отдельные условия использования: [источники и атрибуция](docs/media-credits.md). Для распространения роликов используйте материалы с подходящими разрешениями.

## Используемые LLM-провайдер, модели и их назначение

Внешние модели вызываются через **OpenRouter API** с одним `OPENROUTER_API_KEY`. OpenRouter служит шлюзом к моделям Xiaomi, Google и Fish Audio. Google ADK управляет агентами и их инструментами; отдельный ключ Google для этого не нужен.

В `.env.example` заданы следующие модели по умолчанию:

| Настройка | Модель и разработчик | Что делает в проекте |
|---|---|---|
| `ORCHESTRATOR_MODEL` | Xiaomi · `xiaomi/mimo-v2.6-pro` | Продюсер выбирает следующий этап, делегирует работу и назначает адресные правки. Монтажёр на той же модели составляет план сборки и вызывает инструменты рендера и проверки. Отдельный вызов проверяет исследование по выдержкам из источников. |
| `WRITER_MODEL` | Xiaomi · `xiaomi/mimo-v2.6-pro` | Пишет и исправляет сценарий: реплики выбранных рассказчиков, сцены, запросы иллюстраций и подписи с учётом темы, языка и длительности. Также разбирает спорные замечания к фактам сценария. |
| `SPECIALIST_MODEL` | Xiaomi · `xiaomi/mimo-v2.6-flash` | Исследователь собирает факты и источники через веб-поиск OpenRouter/Exa. Визуализатор ищет и выбирает иллюстрации Wikimedia Commons для сцен. При повторяющихся ошибках инструмента эти агенты переводятся на `ORCHESTRATOR_MODEL`. |
| `VISION_MODEL` | Google · `google/gemini-3.8-flash` | Осматривает найденные изображения и выбранные кадры готового ролика: релевантность иллюстраций, читаемость и расположение текста. Также разбирает спорные замечания к исследованию. |
| `SCRIPT_REVIEW_MODEL` | Google · `google/gemini-3.8-flash` | Перед озвучкой отдельно сверяет сценарий с запросом пользователя и выдержками из источников, возвращает конкретные замечания для исправления. |
| `AUDIO_REVIEW_MODEL` | Google · `google/gemini-3.8-flash` | Слушает дорожку из итогового видео, расшифровывает её и проверяет разборчивость, произношение, обрывы слов и слышимые дефекты склейки. |
| `TTS_MODEL` | Fish Audio · `fish-audio/s2.1-pro` | Синтезирует речь по репликам сценария, в том числе с голосовым образцом персонажа. Это модель озвучки, а не агент, принимающий решения. |

У рассказчика может быть собственная `tts_model`, которая имеет приоритет над `TTS_MODEL`. Встроенные пресеты используют Fish Audio. Для добавленного пользователем рассказчика без голосового образца API назначает стандартный голос Google · `google/gemini-3.8-flash-lite-tts`, также через OpenRouter.

LLM нужны для работы со свободным запросом: отбора сведений, написания связного сценария и выбора доработок по результатам проверок. Агенты вызывают ограниченный набор инструментов и передают результаты как структурированные артефакты. Модели не генерируют видеокадры: ролик собирается из фона, портретов, иллюстраций, озвучки и субтитров.

Распознавание речи и тайминги выполняет локальный **Whisper `small`** через `faster-whisper` (`WHISPER_MODEL`), а сборку видео и технические проверки — FFmpeg, PyAV и Python. Эти операции не требуют LLM API. Модельные рецензии помогают находить ошибки, но итоговый ролик всё равно требует просмотра человеком.
